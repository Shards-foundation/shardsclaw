# Shardsclaw Rebrand Inventory (Baseline)

Inventory source: initial full upstream checkout at `14851272`, on branch `chore/shardsclaw-rebrand`. The counts below are pre-edit baselines; the working tree now contains approved planning, package/CLI identity, and Control UI branding changes. Full Git history was fetched before implementation.

## Reproducible baseline

Run from the repository root:

```bash
git ls-files | wc -l
git grep -Il -i -E 'openclaw|open claw|open-claw' | wc -l
git grep -i -E 'openclaw|open claw|open-claw' | wc -l
git ls-files | grep -i -E 'openclaw|open-claw' | wc -l
git grep -Il -i -E 'openclaw|open claw|open-claw' | awk -F/ '{print $1}' | sort | uniq -c | sort -nr
```

Observed baseline: **60,916 tracked files**, **40,108 text files with one or more name matches**, **370,998 matching text lines**, and **3,133 tracked paths containing the old name**. Counts are search baselines, not a goal of zero matches; permitted factual and compatibility matches must remain.

## Canonical owners and representative matches

- `package.json`: package name `openclaw`, metadata namespace key `openclaw`, GitHub homepage/bugs/repository URLs, `openclaw` executable, and historical author attribution to OpenClaw Foundation. Candidate product/package/URL fields require separate treatment; author attribution is factual and must not be replaced with Shards Inc.
- `README.md`: old product branding, official OpenClaw domains, npm badge/install command, upstream governance and authorship claims, upstream community links, and upstream-specific artwork. Rewrite as Shardsclaw source-repository guidance, clearly disclose derivation/provenance, use only destinations controlled/confirmed for Shardsclaw, and do not claim unowned services or published package availability.
- Runtime/config/state: active contracts include `OPENCLAW_HOME`, `OPENCLAW_STATE_DIR`, `OPENCLAW_CONFIG_PATH`, `OPENCLAW_PROFILE`, many additional `OPENCLAW_*` environment variables, `.openclaw`/profile directories, `openclaw.json`, and named service identities. These are existing user-data and service contracts; preserve discovery/aliases and do not migrate destructively.
- Apps/platforms: the product display name and icons can be rebranded; Android Java/Kotlin package namespaces, app IDs, iOS/macOS bundle/signing identities, registered OAuth/callback IDs, and service identifiers are distinct technical contracts. Preserve them unless ownership and a tested migration are established.
- `LICENSE` carries `Copyright (c) 2026 OpenClaw Foundation` under MIT and must remain intact. Keep third-party notices and copyright/license material unchanged.
- `CHANGELOG.md`, `CHANGELOG/`, contributor/author credits, upstream governance history, source links and original release facts remain historical/provenance records, not current Shardsclaw product copy.
- Generated files, schemas, native asset catalogs, snapshots, lockfiles, and bundled docs must be updated by their canonical source/generator. A match in generated output is not permission to hand-edit it.
- The [official OpenClaw brand kit](https://github.com/openclaw/carapace/tree/main/brand-kit) and [Carapace rights guidance](https://carapace.design/resources/brand-and-assets/) say public availability is not a redistribution license and prohibit copying logos, mascot artwork, photos, or illustrations without recorded permission. Do not reuse or alter those assets. The user approved an independent shard-and-claw motif in midnight blue, electric teal, and silver.
- Control UI: `ui/src/app-navigation.ts` is a browser-title default; `packages/gateway-protocol/src/theme.ts` owns fallback theme branding; `ui/public/manifest.webmanifest` owns PWA display names. `ui/config/control-ui-social-preview.ts` generates social artwork from `ui/public/favicon.svg`. Keep public asset URLs stable and regenerate derivatives from canonical sources. `ui/public/provider-icons/` and cloud/provider icon collections are separately attributed or licensed and are not rebrand assets.
- UI/native localization: use canonical English/source records and each repository-owned workflow (`pnpm ui:i18n:baseline`, `pnpm ui:i18n:verify`, `pnpm native:i18n:baseline`, `pnpm native:i18n:verify`, `pnpm android:i18n:check`); never hand-edit generated translations or memory files.
- Native identities are persistent/service contracts: keep Android `ai.openclaw.app` / `ai.openclaw.wear` package IDs and namespaces, iOS bundle IDs and `group.ai.openclawfoundation.app.shared`, macOS `ai.openclaw.mac` and LaunchAgent/Keychain/defaults identities, and Linux `ai.openclaw.linux`. Preserve associated URL schemes, app groups, provider authorities, Wear/Bonjour paths, updater/signing IDs, and CLI/state integration unless a separately tested migration and account ownership are proven.
- Delivery: release/workflow promotion and npm publishing are deliberately gated on `openclaw/openclaw`; retain those gates, registry trust, deployment credentials, and external release environments. Workflow display labels may change only when this does not alter publication, signing, deployment, trigger, permission, artifact, or destination semantics. Keep official upstream image references as explicit external dependencies until a Shards-inc image actually exists.

## Disposition policy

| Match class                                                                                       | Planned action                                                                                                                                                     |
| ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Active Shardsclaw display copy, app labels, logos, banners, first-party help and repository links | Replace with Shardsclaw identity and verified in-repository or Shardsclaw-controlled destinations.                                                                 |
| New-install package/CLI metadata and internal-only symbols/file names                             | Rename to `shardsclaw` where local references and build/test contracts can be updated completely; keep an `openclaw` command alias if required for existing users. |
| Existing config/state/env/service/protocol contracts                                              | Preserve; add a Shardsclaw preferred display or alias only when tested to use the same authoritative state and avoid duplicate stores/services.                    |
| Platform signing/store/OAuth/registered identifiers and upstream-owned domains                    | Do not rename or redirect without proof of ownership and a safe migration; identify residual references as externally controlled.                                  |
| Legal notices, upstream author credits, third-party notices and historical changelogs             | Preserve verbatim except correcting a demonstrable error; add explicit fork/provenance notice to new front matter where necessary.                                 |
| Generated outputs                                                                                 | Change canonical source and run the owning generator/checker.                                                                                                      |

## No-blind-replacement rule

Search counts are not acceptance criteria. Every module change must be scoped by owner and match class. Any bulk rename must exclude/retain the classes above, update path consumers together, regenerate owned outputs, and pass targeted tests. End-state audit must classify remaining matches and show that none represent stale active Shardsclaw branding; zero remaining OpenClaw matches is neither required nor safe.

## End-state audit (2026-11-02)

Using the same tracked-text and tracked-path search scope as the baseline above, the final scan found 366,826 matching text lines across 40,044 tracked files and 3,126 tracked paths with matches. These counts are not acceptance thresholds: the remaining occurrences fall into the compatibility, legal/provenance, historical, generated/vendor/test-fixture, or externally controlled classes listed above. No stale active Shardsclaw identity was left in the audited product surfaces.

The root manifest's internal self-identity remains unchanged because runtime bootstrap imports depend on it; the preferred Shardsclaw executable and compatibility alias are covered by `test/package-identity.test.ts` and the package build. Persistent state, environment, protocol, and platform identifiers remain unchanged, as verified by the compatibility tests. Original license and author notices remain intact.
